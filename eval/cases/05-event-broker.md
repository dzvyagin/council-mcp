# Брокер событий для биллинга

## Вопрос

Нужен брокер для событий биллинга: 20 000 событий в секунду в пике, 12 потребителей, часть читает с начала дня для пересчёта. Kafka, RabbitMQ или что-то третье?

## Ограничения

- Только on-premise, команда эксплуатации — 3 человека.
- Порядок событий важен в пределах лицевого счёта.
- Хранение событий — 30 дней.

## Что проверить при оценке

- Учтены ли требования к порядку, повторному чтению и хранению.
- Оценена ли сложность эксплуатации для маленькой команды.
- Есть ли план мониторинга лагов и отказоустойчивости.
