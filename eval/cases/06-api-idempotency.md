# Идемпотентность публичного API платежей

## Вопрос

Партнёры повторяют запросы на создание платежа при таймаутах, бывают дубли. Как спроектировать идемпотентность POST /payments?

## Ограничения

- Партнёры не все готовы передавать ключ идемпотентности.
- Ответ на повтор должен совпадать с первым ответом.
- Нагрузка — 500 RPS, несколько инстансов API за балансировщиком.

## Что проверить при оценке

- Где хранится ключ и ответ, сколько и как обеспечивается атомарность.
- Что делать с партнёрами без ключа (естественный ключ, дедупликация).
- Как ведёт себя система при гонке двух одинаковых запросов.
